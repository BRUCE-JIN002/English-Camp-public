# AI 对话与 SSE 流式输出

对话使用带鉴权的 POST 请求建立 SSE 响应，消息增量来自 LangChain Agent，历史保存在 PostgreSQL 检查点中。SSE 是服务端到浏览器的单向流，符合“提交问题后逐步显示回答”的需求。

## 服务端链路

AuthGuard 校验身份 → Controller 用 req.user.userId 覆盖请求体身份 → AccountLockService 获取账号共享锁 → PromptService 解析该用户可用角色 → 可选博查搜索 → 选择普通或深度思考模型 → createAgent → stream。

线程键为 `${userId}-${role}`。检查点初始化使用 AI_DATABASE_URL；历史接口也先验证角色可用，再读取同一线程。共享锁协调账号注销，不负责让同一聊天线程串行执行。

普通 Chat Agent 没有配置数据库 tools；查学习记录的 queryTool 属于摘要模块。联网搜索是应用代码预先调用博查并拼接提示词，不是让聊天 Agent 自主决定调用搜索工具。

## SSE 数据形状

```text
data: {"content":"回答片段","role":"ai","type":"chat"}

data: {"content":"思考片段","role":"ai","type":"reasoning"}

```

每个事件以空行结束。reasoning 来自模型消息的 additional_kwargs.reasoning_content，正文来自 content。服务端最后调用 res.end，没有显式 DONE 事件。

前端 fetch-event-source 支持 POST body 和 Authorization；收到消息后分别累计正文和 reasoning。onopen 校验响应成功且 Content-Type 包含 text/event-stream，避免把登录错误 JSON 当成聊天流。

## 多角色切换

Chat 页面按 role 保存独立 Conversation，包含 messages、controller、loading、loaded。开始回复时捕获目标消息对象，后续 chunk 写入这个对象；用户切到 B 时，A 的流继续写 A。切回 A 不用历史快照覆盖正在生成的消息。

删除角色和页面卸载会终止对应连接。前端 AbortController 停止接收，不代表服务端已取消模型计算：当前 Controller 未显式把连接关闭传播到模型调用。

## 当前需要继续完善的语义

编辑或重新生成会截断前端列表，但服务端仍向原 checkpoint 追加新 HumanMessage，没有按消息 ID 回滚历史。UI 看起来像“修改旧消息”，持久化语义却未完全对应。还需考虑同一线程多标签页并发、流中途异常、心跳、背压和上游取消。

检查流式效果时看首个 chunk 是否及时到达，而不是只看最终全文。两层 Nginx 都要关闭缓冲，见部署篇。
