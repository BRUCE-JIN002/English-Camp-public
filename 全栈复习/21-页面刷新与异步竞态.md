# 页面刷新流式会话与滚动加载

异步竞态的共同问题是：请求发出时的页面、账户或选中项，响应回来时可能已经改变。取消请求节省资源，校验结果归属防止污染状态，二者职责不同。

## usePageRefresh

hook 监听 route.fullPath 和 userId，并响应 visibilitychange、focus、pageshow。50ms 定时器合并短时间内重复触发；每次 schedule 增加 revision，使旧请求立即失效。

调用方拿到 isCurrent 函数，提交状态前检查它。卸载会标记 disposed、增加版本、取消定时器并移除事件。hook 不强制重新挂载页面，因此能保留编辑草稿；它也不自动取消网络，需要调用方按需补 AbortController。

```ts
// 使用模式示意，接口调用由具体页面提供
usePageRefresh(async (isCurrent) => {
  const result = await loadData();
  if (!isCurrent()) return;
  items.value = result;
});
```

## Chat 的归属隔离

每个 role 有独立 Conversation。stream 回调捕获 state 和 target，不再用“当前选中的列表”接收所有流，所以 A 回复期间切换 B 不会串台。历史加载检查 Map 中同 role 是否仍对应同一 state；删除或替换后的旧结果不能覆盖新对象。

停止或卸载使用 abort；完成回调还比较 controller 身份，避免旧请求结束时清掉新请求的 loading 状态。页面内不同会话可同时生成，不代表服务端同一个 thread 已串行化。

## 已掌握列表无限加载

Learned 页面结合分页和 IntersectionObserver 加载更多。移动端观察实际滚动容器，桌面观察视口；首屏内容不足时继续补页，避免 sentinel 不移动导致无法再次触发。错误时停止自动循环，交给显式重试恢复。

稳定排序减少分页顺序漂移，但 offset 分页遇到并发新增/删除仍可能重复或漏项。大规模数据可评估游标分页，不能仅凭添加 id 排序声称完全无漂移。

## 可复用思路

把每次异步操作看成带 owner 和 revision 的任务：只有 owner 仍有效、revision 仍相同，才允许写状态。这个模式同时出现在页面刷新、tracker 访客注册和媒体播放中。

现有 node:test 用例覆盖页面切换、账号变化、卸载、聊天并发和滚动错误恢复。这些以模拟运行时为主，不替代真实浏览器布局、触摸与网络测试。
