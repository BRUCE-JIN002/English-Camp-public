# 测试分层与项目改进清单

测试要回答具体风险，而不只是统计用例数量。本项目同时存在服务单元测试、前端模拟运行时测试、数据库集成脚本和需要浏览器验证的交互。

## 已有测试入口

| 层次 | 入口 | 能验证什么 |
| --- | --- | --- |
| Jest 服务测试 | server 的 *.spec.ts | 支付、用户、注销、发音、邮件和 Agent 的分支逻辑 |
| node:test | apps/web/tests/*.test.cjs | 刷新竞态、聊天切换、滚动加载、课程高亮 |
| 部署脚本测试 | deploy/migrate-with-retry.test.cjs | 连接错误分类、重试次数、危险失败停止 |
| 集成脚本 | agents.integration.ts、learned.integration.ts | 依赖真实环境的接口与数据行为 |
| Jest 浏览器 API 模拟 | browser-voice.spec.ts、pronunciation-player.spec.ts | 模拟语音识别、音频事件、清理与拒绝播放 |
| 真实浏览器验收 | 运行中的页面与设备 | 实际播放、布局、触摸及浏览器策略 |

服务 Jest roots 和 testRegex 会收集 server/apps/server/test 下的 spec；其中两个语音相关文件使用 VM 和模拟浏览器 API，不会启动真实浏览器。agents/learned 的 integration.ts 脚本不匹配这个 spec 规则，需要单独运行，且可能创建或删除数据；先读脚本并配置独立测试环境。

## 常用命令

```bash
# 项目根目录，前端模拟测试与迁移脚本测试
node --test apps/web/tests/*.test.cjs deploy/migrate-with-retry.test.cjs
# 指定源码单元测试目录；语音 API 模拟用例可通过完整 Jest 命令另行覆盖
pnpm --filter @en/server test --runInBand --testPathPattern='(apps/server/src|apps/ai/src|libs/shared/src)'
# 类型检查与构建
pnpm --filter @en/tracker build
pnpm --filter @en/web build
pnpm --filter @en/server build
pnpm --filter @en/server exec nest build ai
```

Jest 配置已为共享 ESM .js 设置 ts-jest allowJs。新增共享运行时代码时要同时验证前端 Vite 和后端 Jest/Nest，不能只靠 TS 类型声明判断兼容。

## 从源码能看出的改进优先级

| 主题 | 当前缺口 | 下一步可验证动作 |
| --- | --- | --- |
| 身份与输入 | Socket、digest、上传、埋点有鉴权缺口 | 明确访问者，补运行时校验与拒绝用例 |
| 密码与会话 | 服务端直接比较密码；双 Token 同为 7 天 | 引入安全密码存储、会话撤销及刷新失败测试 |
| 内容渲染 | marked 后直接渲染 HTML | 净化 HTML 并覆盖恶意链接/标签用例 |
| 学习统计 | 记录与计数多步写，catch 范围过大 | 事务与精确错误分类，并发验证 |
| 响应协议 | success 固定 true | 对齐业务错误、HTTP 状态和前端处理 |
| 日报 | 时区不明确、内容提前生成、无显式重试 | 固定业务日期，补投递状态和故障恢复 |
| 聊天历史 | UI 编辑不回滚检查点 | 定义消息 ID、分支或重新生成语义 |
| 可观测性 | 缺少成体系的请求与任务关联 | 关联 requestId/jobId，统计失败与延迟 |

这是一份代码阅读得到的改进清单，不是完整安全审计，也不是已完成修复。练习时每次挑一条，先写失败场景，再改实现和测试，最后更新对应笔记。
