# English AI 简历项目描述

以下条目以仓库现有功能为基础。职责、开发周期和个人贡献请按实际经历填写，不默认认领独立开发，也不填写未经测量的业务或性能数据。

## 精简版

**English AI 英语学习平台**

技术栈：Vue 3、TypeScript、NestJS、Prisma、PostgreSQL、LangChain、DeepSeek、Redis、BullMQ、MinIO、Socket.IO、Docker。

- 使用 pnpm workspace 组织 Vue 前端、埋点 SDK、共享类型和 NestJS 双后端应用，串联单词查询、课程学习、学习记录及用户设置。
- 集成 DeepSeek 与 SSE 流式对话，使用 PostgresSaver 保存用户与角色维度的历史，支持自定义 Agent；前端按角色维护会话状态，避免切换时增量消息串写。
- 接入支付宝支付，基于验签、订单金额核对、条件更新与事务实现重复回调幂等，并通过主动查单补偿漏回调，提交后推送支付通知。
- 接入腾讯 TTS 与 MinIO 音频缓存，使用进程内请求合并、合成限流和统一播放器复用词库发音，处理 Range 请求及移动端点击播放。
- 使用 BullMQ 组织学习摘要与邮件任务，增加跨服务账号清理流程；通过服务单元测试与前端异步场景测试验证关键分支。

## 按岗位选择展开

前端岗位优先展开 Vue 状态归属、聊天多流隔离、页面刷新 revision、无限滚动与音频生命周期；后端岗位优先展开支付条件更新、唯一约束、队列异常传播和注销清理；全栈岗位可以选部署路径、端到端业务链路与验证方法。

可用的深入表述：

> 为聊天页面按角色维护独立消息数组与 AbortController，流回调绑定发起时的目标消息；角色切换期间保留后台生成，并通过状态归属检查避免历史响应覆盖其他会话。

> 在支付结算事务中对未完成订单执行条件更新，只有首次更新成功才 upsert 课程权益；异步通知和主动查单复用结算逻辑，数据库提交后再触发前端通知。

这些表述说明做法和作用，没有声称未经测试的提升比例。

## 删除旧稿中不成立的表述

| 旧说法 | 当前准确口径 |
| --- | --- |
| 10 个数据库模型 | 13 个业务模型，检查点另外管理 |
| sendBeacon 保证不丢数据 | 使用 Beacon 上报，存在交付边界 |
| Socket 房间保证用户隔离 | 房间用于路由，握手身份验证待完善 |
| 短 accessToken 长 refreshToken | 当前都为 7 天 |
| Chat Agent 自动查询用户单词 | queryTool 位于日报 Agent |
| 完整向量 RAG | 当前为搜索结果拼接增强 |
| 所有学习状态事务一致 | 支付结算有事务，学习保存尚需完善 |
| 语音播报基于 SpeechSynthesis | 当前单词发音为腾讯 TTS 与 HTMLAudioElement |
| 完整微服务治理和高并发能力 | 双后端应用，规模能力需真实测试 |

面试时主动说明最重要的不足，并给出可验证改进步骤，比把每项能力都写成完整方案更可信。
